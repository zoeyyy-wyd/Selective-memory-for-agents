# 全部测试结果

数据:LongMemEval-S,500 题(每题约 47 场对话、10.3 万 token 历史),按类型分层切成 dev 100 / test 400(`data/split_dev100_seed0.json`),test200 是 test 里按类型各取一半(`data/test200_seed0.json`,197 题)。
判分:GPT-4o,LongMemEval 官方 prompt,温度 0;同一答案两次判分可差 ±2 题,4 题以内的差别不作结论。
准确率口径:全部题数(含"无法回答"题,正确弃答算对)。

## 1. 最终配置(`configs/raw_turns.yaml`)

抽取 Qwen3-8B-AWQ(v3-detail)→ bge-m3 + BM25 检索 → 事实打包 2k token + 原文轮 6k token → gpt-4.1-mini 回答。存储不限。

| 集合 | 题数 | 正确 | 准确率 |
|---|---|---|---|
| dev100 | 100 | 76 | 0.76 |
| test200(held-out) | 197 | 161 | **0.82** |
| 合计 | 297 | 237 | **0.80** |

分类型:

| 类型 | dev100 | test200 |
|---|---|---|
| knowledge-update | 14/15 | 27/28 |
| single-session-user | 12/13 | 24/26 |
| single-session-assistant | 11/11 | 21/22 |
| temporal-reasoning | 19/25 | 41/51 |
| multi-session | 13/24 | 34/48 |
| single-session-preference | 2/6 | 6/12 |
| 无法回答题 | 5/6 | 8/10 |

上限:把标注证据原文直接给 gpt-4.1-mini(oracle),dev100 = 84。

## 2. 存储预算曲线(原文计入 B)

dev100。B 是存储 token 占历史 token 的比例;原话作为二级条目占预算,事实优先。

| B | 预算 tok | swap | fifo | lru | 原文进上下文 |
|---|---|---|---|---|---|
| 0.015 | 1.5k | **34** | 30 | 23 | 0 |
| 0.03 | 3.1k | **46** | 31 | | 0 |
| 0.06 | 6.2k | **49** | | | 0 |
| 0.125 | 12.9k | **60** | 60 | | 2.1k |
| 0.25 | 25.8k | **72** | | | 6k |
| 不限 | 113k | **76** | | | 6k |

- B ≤ 0.06 预算全被事实占满,数字等于只抽事实的系统;swap 对 fifo 在 0.03 差距最大。
- 0.125 事实全存下(约 9k),余量给原话;swap 与 fifo 相同是因为事实没被淘汰过。
- 更早的只事实版本(glm 读者、v3 抽取)在 B=0.015:swap 0.24、去 Hawkes 0.22、fifo 0.21、lru 0.17;换 gpt-4.1-mini + v3-detail 后 swap 0.34。

test200 的预算曲线和 297 题合并:见第 6 节。

## 4. 试过、没采用的

| 变体 | dev100 | 结论 |
|---|---|---|
| 读者 gpt-4.1 / gpt-4o(只事实,strict) | 48 / 48 | 大读者弃答更多;grounded prompt 55 |
| 读者 glm-5.3-free(网关) | 51 | 与 gpt-4.1-mini 持平,慢 10 倍且空响应多 |
| 读者 prompt notes / notes2 | 69 / 69 | temporal 掉 2-4,计数题涨 1,净负 |
| 原文预算 8k | 75 | 与 6k 噪声内 |
| 每会话先保一轮(raw_diversity) | 65 | 挤掉高分会话的相邻轮 |
| 直检原文轮权重 0.5 | 66 | 高分直检轮被压出预算 |
| 原话免过 sieve 门槛 | B=0.015: 15 | 原话占掉三分之二预算 |
| 原话作为覆盖目标 | 不限: 65-70 | 短废话成为最便宜的自覆盖项;归一化基准被抬高,证据短轮被拒 |
| 合并(consolidation) | — | 摘要 229/230 被蕴含检查拒绝,占 ingest 97% 时间,关闭 |

## 5. 失败归因(dev100,只事实 59 那版的 40 道失败题)

| 阶段 | 题数 |
|---|---|
| 抽取没抽到(7 题在助手轮,5 题是用户长轮里的顺带一提) | 14 |
| 答案要跨会话数数/加总 | 13 |
| 在上下文里读者答错/弃答 | 10 |
| 存/检索/打包丢失 | 3 |

40 道失败题涉及 80 个证据会话,80 个都有条目进了读者上下文:检索覆盖不是问题,改写丢细节才是。这是"读者看原文"这一步的依据。

## 6. test200 预算曲线,以及 297 题合并

| B | test200 swap | test200 fifo | dev100 swap | **合并 297 swap** | 合并 fifo |
|---|---|---|---|---|---|
| 0.015 | 44/197 = 0.22 | 35/197 = 0.18 | 34 | **78/297 = 0.26** | 65/297 = 0.22 |
| 0.03 | 68/197 = 0.35 | 49/197 = 0.25 | 46 | **114/297 = 0.38** | 80/297 = 0.27 |
| 0.125 | 119/197 = 0.60 | 119/197 = 0.60 | 60 | **179/297 = 0.60** | 179/297 = 0.60 |
| 0.25 | 153/197 = 0.78 | | 72 | **225/297 = 0.76** | |
| 不限 | 161/197 = 0.82 | | 76 | **237/297 = 0.80** | |

- 曲线形状和 dev 一致:小预算 swap 明显优于 fifo(0.03 时 0.35 对 0.25),0.125 起事实全存下、两者相同,0.25 起原话大量存活。
- test200 在小预算下比 dev 低(0.22 对 0.34),不限量下比 dev 高(0.82 对 0.76):dev 的 100 题在写入选择上偏容易、在阅读上偏难,这是抽样差异,297 题合并的数更稳。

## 7. 抽取与运行成本

- 抽取:Qwen3-8B-AWQ,单张 L4,16 路并发,约 4 秒一场。dev 4564 场 6.7 小时;test200 8510 场 9.5 小时。格式错误率 0.85%。
- 一次 100 题读侧评测(ingest 缓存热):约 15 分钟;带淘汰的预算档约 25-35 分钟;API 费用约 1 美元(gpt-4.1-mini 回答 + gpt-4o 判分)。
- 六个分片并行会撞 OpenAI 每分钟 20 万 token 的限额,三片为宜。
