# LongMemEval 上 80%+ 系统的做法调研

2026-09-14。目的:我们的流水线(Qwen3-8B 抽事实 → bge-m3 稠密 + BM25 RRF → 预算打包 → gpt-4.1-mini 读)在 dev100 上 59,目标 80,看别人是怎么做到的、差在哪。四篇系统报告加 LongMemEval 原文,只记和我们有关的做法与数字。

## 逐个系统

### Memanto(arXiv 2604.22085)— LongMemEval-S 89.8

- **存什么**:原始对话文本按块存,写入时**零次 LLM 调用**,不抽事实、不做摘要。类型标签是人工打的,在评测里等于纯原文 RAG。
- **怎么读**:单查询稠密检索(自家二值向量索引),没有 BM25、没有重排、没有查询改写、没有时间处理。最终设置 k 最多 100 块、阈值 0.05,每题送读者 4 到 5 万 token;k≈60 以上不再涨。
- **读者**:Claude Sonnet 4 调参,最终数用 Gemini 3。prompt 抄 Hindsight 仓库(反拒答,判分宽松)。
- **分类型**:SS-user 95.7、SS-assistant 100、SS-pref 93.3、multi 81.2、KU 93.6、temporal 88.0。
- **逐步消融**(同一读者):k=10 → **56.6**;k=40 → **77.0**;换 prompt → 79.2;k≤100 → **85.0**;换 Gemini 3 → 89.8。召回宽度一项 +26 分,prompt +2,读者 +5。
- 剩余错误归因:关键句埋在大块无关文本里没被召回,不是读者读错。

### Cognis / Lyzr(arXiv 2604.19771)— 87.2(GPT-4.1)/ 92.4(Opus 4.6)

- **存什么**:两份。原始消息一份索引(含助手轮);抽取事实一份,带类别、事件时间、版本链(is_current / replaces_id)。抽取时先检索相近旧记忆,LLM 输出 ADD / UPDATE / DELETE / NONE。
- **怎么读**:查询意图分析(时间词 → 时间加权;历史词 → 允许旧版本);稠密两阶段(256 维粗筛 200 → 768 维精排),并行 BM25(OpenSearch),RRF 加权 0.7/0.3;时间加权 `0.6·融合分 + 0.4·max(0.1, 1−|事件时间−问题日期|/窗口)`;bge-reranker-v2-m3 交叉编码重排;送读者 **50 条**。检索指标 Hit@K 0.83、P@K 0.10。
- **读者**:GPT-4.1 主表;8 个读者 83.4(Gemini 3 Flash)到 92.4(Opus 4.6),浮动 9 分。prompt:带时间戳、冲突取最新、相对日期换绝对、逐步推理。
- **分类型(GPT-4.1)**:SS-user 100、SS-assistant 87.5、SS-pref 93.3、KU 93.6、multi 82.7、temporal 79.7。
- **消融(LoCoMo 上)**:BM25 后端换成 OpenSearch 收益最大;LLM 查询分解**反而掉分**(单跳 −1.3、开放域 −14.2);RRF 0.7/0.3 最好。temporal 错误:34% 没召回、28% 时间加权加错、22% 重排次序、16% 读者。
- 自述弱点:助手内容只以原始消息存、没抽,SS-assistant 是它最弱的单会话类型。

### MemReader(arXiv 2604.07877)— 83.0(Qwen3-4B 抽取,gpt-4.1-mini 读)

- **存什么**:只存抽取单元 `{key, type, value(第三人称、绝对日期), tags}` 加每块 120-200 词摘要;4B 模型按轮做 ReAct(add / buffer / search / ignore),写前先检索旧记忆解决指代。没有单元到原文轮的链接。
- **怎么读**:沿用 MemOS,论文没给 k、向量模型、重排。时间在写入时归一到事实文本里。
- **读者**:gpt-4.1-mini(也是判分)。
- **分类型**:SS-user 94.3、SS-assistant 73.2、SS-pref 90.0、multi 73.7、KU 91.0、temporal 84.2。同一评测框架:EverMemOS 83.0、MemOS 77.8、Memobase 72.4、Mem0 66.4、Zep 63.8。
- **值得记的**:4B 模型每次抽取 922 token 比 0.6B 的 1166 token 更准,即"选得对"胜过"抽得多";GRPO 比 SFT 高 3 分,主要在 KU 和 temporal。抽取 prompt 要求"不要省略用户可能记得的任何信息,完整优先于简洁",助手内容只在用户回应过时才抽。SS-assistant 73 是它的短板,和只抽用户侧一致。

### LIGHT(arXiv 2510.27246,BEAM 基准,不是 LongMemEval)

- **存什么**:每对话轮后用 Qwen2.5-32B 抽事实和摘要,只作**检索键**(bge-small 向量),**原始对话段作为值**返回给读者;另有一份累计"草稿本"(超 3 万 token 时压到 1.5 万),和最近 z 轮工作记忆。
- **怎么读**:稠密 top-15 最好(k=5 到 15 涨 6 到 11 分,k=20 略降);SPLADE 稀疏在 ≤1M 时比稠密强;读者上下文 32K。
- **消融**:10M token 时去掉检索损失最大;100K 时去掉噪声过滤损失最大。

### LongMemEval 原文(arXiv 2410.10813)的三条结论

设置:Stella 1.5B 检索,GPT-4o / Llama-3.1 读,取 top-10,按时间排序,消融在 LongMemEval-M 上。

- **会话切分到轮**:轮级单元比会话级好;把抽取的事实/摘要当**值**会因信息丢失而掉分,只有 multi-session 例外。Llama-8B 读者超过约 3K 检索 token 就崩,GPT-4o 到 20K 以上还在涨。
- **事实增强键(键 = 轮文本 + 用户事实)**:轮级 R@10 0.692 → 0.784,GPT-4o 准确率 0.670 → 0.720;平均召回 +9.4、准确率 +5.4。只用事实做键比原文差(R@10 0.654),检索时做分数融合不如索引时拼接。
- **时间感知查询扩展**(GPT-4o 抽日期范围再过滤):temporal 子集 R@10 0.550 → 0.722(轮级);用 Llama-8B 抽范围会在非时间题上乱抽而掉分。
- 读法:JSON 列出条目 + 逐条摘记(Chain-of-Note)在 oracle 检索下 GPT-4o 0.862 → 0.924。最佳流水线剩余错误 40-50% 是"检索对了、生成错了"。

## 共同点(对照我们缺什么)

1. **读者看原文**。Memanto 直接检索原文块;Cognis 原始消息和事实并存;LIGHT 事实只做键、原文做值;LongMemEval 原文证明事实当值会掉分。我们的读者只看 Qwen3-8B 的改写,抽取漏掉的东西读侧无法弥补。→ 已做,59 → 71。
2. **召回宽度大 5 到 10 倍**。Memanto k=10 是 56.6(正好是我们的水平),k=40 是 77;Cognis 送 50 条;LongMemEval GPT-4o 到 20K token 还在涨。
3. **轮级单元 + 事实增强键**,不是事实级单元。→ 正在测(原文轮索引)。
4. **助手轮也索引**。不索引的系统 SS-assistant 都在 71-73;Memanto 原文检索 100。
5. **交叉编码重排**(bge-reranker-v2-m3),Cognis 的 temporal 错误 22% 是次序问题。
6. **时间处理**:事实带绝对日期和事件时间字段;强模型抽日期范围过滤(+11 到 +17 召回)。弱模型做这个会帮倒忙。
7. **知识更新用版本链**而不是并存两条矛盾事实(Cognis、MemReader KU 91-96)。我们已有有效期链,方向一致。
8. **读者 prompt** 值 2 到 10 分:条目按时间、冲突取最新、逐条摘记、反拒答。→ 我们试了两版都没净收益(69 对 71),暂放。
9. **不值得做**:LLM 查询分解(Cognis 掉分)、知识图谱、换读者(8 个读者浮动 9 分;MemReader 用 gpt-4.1-mini 就到 83)、继续雕抽取措辞。

## 对我们的含义

- 59 → 71 那一步就是第 1 条。到 84(gpt-4.1-mini 看完美证据的上限)剩下的靠第 3、4、5 条。
- 这些系统都没有存储预算的概念;在 B=0.015 的预算模式下原文能不能进、怎么计费,是我们自己要定的。
- 数字口径注意:各家判分模型和 prompt 不同(Memanto 用 Claude 判且宽松,Cognis 用 GPT-4.1 分类型 prompt),互相之间不能直接比,只看趋势。
